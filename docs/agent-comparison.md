# 지역 에이전트 비교 계약

2026-10-20 `regional-comparison-1`을 고정했다. [계약](../scenarios/comparison/contract.json)은 사례 hash·한도·채택 기준을 담는다. 아직 협업 우월성·실제 모델 품질은 평가하지 않았다. 기존 [6개월 fake 비교](evaluation.md)는 회귀 검증으로 유지하며 아래 공정 비교를 대신하지 않는다.

## 사례와 비교군

개발 8건과 잠금 평가 24건은 [생성 코드](../scripts/generate_comparison.py)로 만든 합성 도전 사례다. 평가 세트는 정상, 결측/기간, 원천/연령, 신호 충돌, 자원 부재/만료, 자격 불명 6유형×4건이다. 강남·춘천 및 성별×4연령을 포함한다. 균형 도전 세트이지 현장 빈도가 아니다. 실제 집계 재생은 이 세트에 섞지 않는다.

입력과 라벨은 별도 JSON이며 모델에는 입력의 관측과 도구 결과만 전달한다. 개발 세트는 정상·결측/기간 각 2건, 나머지 유형 각 1건이다. 개발자가 작성한 라벨은 독립 검수 전이다. 공개 저장소의 고정 사례이므로 비공개 시험이라는 뜻은 아니다. 잠금 이후 프롬프트·규칙 조정은 개발 세트로만 하고, 시험 변경이 필요하면 새 버전과 이유를 남긴다. 자동 hash 확인은 무단 변경 감지이며 독립성을 보증하지 않는다.

- A 결정적 기준선: 관측 순서의 판정 가능 후보 최대 3개와 필수 한계를 반환한다. 도구 스냅샷 추가 조회·자연어 해석을 하지 않는 정보 차이를 명시한다.
- B 단일 에이전트: 같은 에이전트가 집단 근거를 조회하고 초안을 만든 뒤 자기 검토한다. 조회 이후에는 새 초안과 자기 검토가 필요하다. 타당한 초안은 자기 검토 후 유지할 수 있으며 변경 자체를 품질로 세지 않는다. 상한 안에 끝내지 못하면 미완료로 남긴다.
- C 협업: 현재 구현에서 분석자와 검토자가 같은 조회 도구·초기 정보·모델·총 호출 상한을 공유한다. 기본 A/B 절차 실행과 `--study` A/B/C 실행을 구분한다.

도구는 관측된 집단 ID로 고정 근거 스냅샷을 조회한다. 임의 파일·네트워크에 접근하지 않는다. 조회 불가도 결과로 기록한다. 자원 후보의 개인 자격·정원은 확인된 자원으로 승격하지 않는다. 모든 결과는 담당자 검토용이며 승인 우회나 외부 전송이 없다.

## 사전 고정 한도와 채택 규칙

`LLM_RUN_BUDGET_USD`로 실행당 예약 비용도 누적 예산과 함께 제한한다. 비교 실행은 계약의 값을 사용한다. B/C 각각 총 모델 호출 6회, 실행당 추정 비용 $0.02, 완료 판단 기한 120초다. 개별 API 호출은 기존 timeout을 사용하므로 120초는 프로세스 강제 종료 시각이 아니다. 기한 이후 돌아온 출력도 성공으로 채택하지 않는다. 기존 누적 예산을 그대로 적용하며 이 계약은 예산 증액이나 초기화를 허용하지 않는다. live 반복 목표는 사례당 3회이며 24사례를 72개 독립 사례로 세지 않는다. 예산이 부족하면 미실행 분모와 사유를 남긴다.

주요 지표는 중대 오류 없이 실행 가능한 계획/전체 24사례다. 미실행·실패·timeout·한도 초과도 분모에 남긴다. 중대 오류는 허위 근거, 집단→개인 단정, 확인되지 않은 자격 확정, 승인 우회다. 필요한 사람 확인은 허용하되 근거 충분한 사례의 무조건 보류는 실행 가능한 계획으로 자동 인정하지 않는다.

잠정 내부 채택 기준은 A와 B 각각 대비 성공 사례 2건 이상 증가(24건의 8.33%p), 새 중대 오류 0건, 비용·기한 준수, 완전한 독립 사람 평정이다. 결과를 본 뒤 유리하게 바꾸지 않는다. 효과가 불명확하면 기존 안정 경로를 유지한다. 담당자 시간 절감만으로 채택하려면 별도 사전 등록한 과업 평가가 필요하다.

## 사람 평정과 보고

방법 이름을 숨긴 무작위 순서로 2명 이상이 독립 평가한 뒤 불일치와 조정을 보존한다. 검토자의 전문성과 개발 참여 여부를 기록한다. 항목: 실행 가능 여부, 중대 오류 종류, 지지되는 주장/검토 주장, 누락 제약, 적절한 조회·보류, 과도한 보류, 수정량, 과업 소요 시간. 근거와 판단 이유를 함께 남긴다. 누락은 null이다. LLM 심판은 보조이며 사람 평정을 대신하지 않는다.

사례별 승/무/패와 paired 차이, 사례 단위 신뢰구간, 호출·비용·지연·실패를 함께 보고한다. 반복을 독립 표본으로 취급하지 않는다. 불리한 사례를 제거하지 않는다. 조회 제거·검토 제거 비교는 본 비교 후 예산이 허용할 때만 수행하며 미실행이면 명시한다.

## 현재 실행 가능한 범위

`uv run python -m eval.run_comparison --split dev`는 A/B의 fake 절차를 확인한다. `--split test`도 동일한 회귀 실행이며 내용 품질은 계속 null이다. 결과는 `runtime/sample/evaluations/UUID/comparison.json`에 저장한다. 평가 DB에는 자동 재개되는 workflow를 등록하지 않는다. 모델·프롬프트·도구 스냅샷·입력/라벨·코드 hash와 live 단가 기록은 실제 비교 시 함께 고정해야 한다.

live 비교 결과, 독립 평정, 운영 과업, 실제 고립 결과는 이 PR의 완료 주장에 포함하지 않는다.

## A/B/C 실행과 가림 평정

```sh
# 개발 사례 절차 검증
uv run python -m eval.run_comparison --study --split dev
# 잠금 24사례 × 3회 × 3방법: fake 계약 검증, 품질 아님
uv run python -m eval.run_comparison --study --split test
# 기존 누적 예산을 사용하는 실제 모델 실행
uv run python -m eval.run_comparison --study --split test --live
# 방법 이름을 제거한 사람 검토 패킷과 별도 대응키 생성
uv run python -m eval.rate_comparison runtime/.../comparison.json
# 원본 2인 평정과 필요 시 조정 기록 집계
uv run python -m eval.rate_comparison runtime/.../comparison.json --key runtime/.../private-key.json --ratings ratings.json
```

live는 기존 `runtime/local/events.sqlite3`의 예약 비용을 유지한다. 전체 비교의 최대 추가 예약액은 $2.88(24×3×2 LLM방법×$0.02)이며 남은 누적 예산이 부족하면 모델 호출 전 차단하고 미실행 144건을 그대로 남긴다. 결정적 A는 유료 호출 없이 실행한다. 이 금액은 지출 예상이나 증액 승인이 아닌 보수적 실행 여유 조건이다. 실행당 예약 상한과 누적 상한 모두 호출 직전 적용한다. 실패·중단의 기존 예약을 지우지 않는다. 같은 비교를 다시 실행하면 새 run이며 예산을 다시 쓴다.

모든 방법은 동일 입력·스냅샷을 받고, 실행 순서는 사례/반복별 고정 난수 순서다. 보고서는 각 실행 뒤 원자적으로 갱신해 중단·미실행·실패를 보존한다. 고정 스냅샷을 사용하는 C를 평가하므로 동적 정책 조회 연결 효과는 포함하지 않는다. 조회/검토 제거 실험과 실제 담당자 교차 과업은 미실행으로 남긴다.

`packet.json`만 평가자에게 제공하고 `private-key.json`은 평가 종료 전 가린다. 방법명·호출량·반복 번호·방법별 상태 토큰은 제거하고 시스템 오류 코드는 공통 문구로 가리지만 문체가 방법을 암시할 수 있다는 한계가 있다. `ratings-template.json`의 reviewers에는 식별자·전문성·개발 참여 여부를, ratings에는 blind_id·평가자·실행 가능·중대 오류·근거 판단·제약 누락·보류 적절성·수정량·시간·이유를 기록한다. 필드 계약은 [평정 모델](../eval/rate_comparison.py)의 Rating을 따른다. 빈 평정을 자동 채우지 않는다.

2인 평정 불일치는 별도로 보존하고, 조정할 때 adjudications에 독립 검토자의 최종 판단과 이유·보류 판단을 추가한다. 기존 raw_ratings는 남는다. 결과 hash가 다른 대응키, 중복 평정, 알 수 없는 ID, 지지 주장 수가 검토 주장 수보다 큰 기록은 거절한다. 각 방법의 반복 평균 성공 사례 수/24와 사례별 승/무/패를 계산한다. 2,000회 사례 단위 bootstrap은 작은 합성 도전 세트의 불확실성이며 실제 모집단 신뢰구간으로 일반화하지 않는다.

fake, 누락·미조정 평정, 개발 참여자만의 평정, dirty 코드, 미완료 live 실행에서는 채택 결정을 내리지 않는다. 조건이 모두 갖춰져도 결과는 기본 경로 변경 **후보**이며 프로그램이 기본 경로를 자동 변경하지 않는다.

평정·채택 코드의 hash도 실행에 고정한다. 이후 코드가 바뀌면 기록된 커밋의 평가 코드로 평정해야 한다. 조정자는 원평정자와 다른 독립 검토자여야 한다. 모델이 요청한 사람 확인과 시스템 오류·시간/호출 한도를 별도 failure_kind로 구분하며 시스템 실패는 성공으로 평정하지 않는다. 누적 예산은 방법 실행 전에도 다시 확인하지만 동시 실행이 이후 예산을 소비할 수 있으므로, 실제 API 호출 직전의 원자적 예산 검사가 최종 제한이다.
