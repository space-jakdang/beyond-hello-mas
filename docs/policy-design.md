# 통계 기반 정책 설계

새 지역 업무의 현행 흐름은 **동별 정책 대안 세 개 → 개별 검토 → PDF/Word**입니다. 전체 집단 입력, 근거 부족 구상안, 재생성·revision 계약은 [정책 도구](policy-tools.md#동별-정책-제안-세-개), 평가는 [정책 대안 품질](policy-alternative-quality.md)을 참고하세요. 아래 내용은 이전 단일 보고서의 읽기 호환·과거 실행 계약입니다.

기존 정책 추천은 실제 조회된 지원 정보이고, 정책 설계는 담당자가 검토할 새 제안입니다. 타지역의 정책 사례를 찾았다고 해당 정책을 현재 지역 주민이 이용할 수 있다고 판단하지 않습니다.

통계 분석은 같은 척도·집단·기간 안에서 분포·변화·민감도와 자료 결측을 정리하고, 관측된 요인에 대응하는 필요를 정책 탐색으로 전달합니다. 집계 상관이나 높은 단계가 개인의 원인·자격·수요 인원을 입증하지는 않습니다. 인구 분모나 예산 자료가 없으면 해당 수치를 생성하지 않습니다.

정책 설계의 입력은 지역 관측 ID, 통계 결과, 카탈로그 부족, 지정 범위의 정책 조회 결과, 상세 조회로 확인한 유사 정책입니다. 검색 미완료는 `search_incomplete`, 확인된 후보가 있는 경우 `candidate_found`, 지정한 출처·범위를 조회했지만 확인된 후보가 없으면 `no_verified_candidates`입니다. 마지막 상태도 현실의 모든 정책이 없음을 뜻하지 않습니다.

정책 초안은 대상 집단·서비스 제안·유사 사례와 다른 지역 여건·적응 방안·운영 단계·필요 역할·실현 가능성 확인 목록·형평성 위험·효과 검증 계획·담당자 질문을 제공합니다. 기존 정책의 사실은 실제 상세 응답 필드와 정확히 일치하는 인용으로 검증하고, 적응 방안은 인용한 정책 ID와 연결합니다. 문장 유창함은 실행 가능성의 증거가 아닙니다.

모델은 `draft`, `needs_evidence`, `needs_human`만 반환할 수 있습니다. 정상 초안은 확인된 범위의 공백과 인용된 유사 사례의 적응 방안을 요구합니다. 예산·정원·법적 근거는 확인 완료로 생성할 수 없습니다. 사람의 정책 검토 승인도 예산 편성·기관 약정·현장 시행 승인이 아닙니다. 초안은 기존 자원 배정과 별개로 보존합니다.

정책 도구·Supervisor 실행·보고서 검토 화면·독립 평정 입력과 평가 대시보드가 연결되어 있습니다. 실제 전문가 평정과 정책 시행 효과는 별도 실증이 필요합니다.

## 구버전: 다른 관할 정책의 참고 사례 조사

`policy_analogues(local_scope, query, target_group)` MCP 도구는 현지 관할을 제외한 지원 관할에서 검색어가 일치하는 최대 5개 사례를 조회한다. 실시간 상세·출처 URL·조회시각이 있는 정책만 참고 근거로 반환한다. 검색 총건수·다음 페이지·부분 실패·오래된 목록을 함께 보존한다. 대상집단 적합성과 인구·예산·기관의 유사성은 아직 확인되지 않았음을 표시하며 에이전트가 원문을 대조해 적용 차이를 설명해야 한다.

이는 현지 신청 가능 정책 추천이 아니다. 지원 범위는 중앙·서울·강남·강원·춘천이며, 검색어 일치를 통계적 지역 유사성으로 부르지 않는다. 유효한 사례가 없거나 목록이 오래되면 `needs_evidence`로 끝난다.

## Supervisor가 위임하는 정책 설계

지역 업무에서 정책 조사 후보가 없으면 Supervisor가 별도 정책 설계 노드에 결과를 전달한다. 검색이 불완전하거나 카탈로그 필터를 수행하지 않았다면 모델·추가 조회 없이 `needs_evidence`로 보류한다. 확인된 검색 범위의 공백일 때만 설계 에이전트가 검색어를 선택해 `policy_analogues`를 호출하고, 실제 원문을 받은 후 담당자용 구조화 보고서를 작성한다. 에이전트 결정은 최대 2회, 사례 조회는 1회이며 기존 실행의 모델 호출·비용·입력 한도를 공유한다.

보고서에는 관측 근거 ID, 대상, 제공 방식, 참고 정책과 현지 차이, 운영 단계, 필요한 역할, 미확인 비용·정원·법률, 형평성 쟁점, 기준선·비교 방법·성공/중단 기준 합의 계획을 담는다. 처음 5개 공백 집단을 전달하고 나머지 집단 수를 명시하며, 전체 지역을 포괄하는 수요 추정이 아니다. 인용 원문·ID·출처는 서버에서 대조한다. 조회 또는 검증 실패는 근거 보류로 저장된다.

도구 관측과 최종 보고서를 SQLite에 저장해 그래프 재시작 시 재사용한다. 저장 전 외부 조회 도중 종료하면 조회가 다시 실행될 수 있지만, 저장된 관측은 중복 조회하지 않는다. 관찰 화면에서 정책 설계 역할과 도구/근거 전달을 확인할 수 있다. 일반 자원 제안 승인은 정책안의 별도 검토 승인이나 예산·시행을 의미하지 않는다.

## 보고서와 별도 사람 검토

지역 업무·미래 시나리오의 ‘자원 제안’에서 정책 설계 보고서를 읽고 인쇄할 수 있다. 담당자 콘솔의 같은 보고서에는 **정책안 검토 승인 / 보완 요청 / 정책안 반려**가 표시된다. 기존 자원 제안의 승인 버튼과는 별도 저장소·상태이며 예산·법률·시행을 승인하지 않는다. 정책 검토자와 사유는 필수다.

담당자는 제목·현지 제공 방식·운영 단계를 수정해 새 버전으로 저장할 수 있다. 기존 출처·인용 검증은 수정본에도 적용하며, 새 버전은 다시 검토 대기 상태가 된다. 이전 버전의 검토자·사유·내용을 이력에서 확인할 수 있다. `GET /runs/{run_id}/policy-design`과 `POST /runs/{run_id}/policy-design/review`는 버전·revision을 확인해 오래된 화면의 결정을 409로 거절한다. 동일 요청 재시도는 중복 이력을 만들지 않는다. 근거 보완 상태는 검토 승인할 수 없다.

정책 조사 위임에는 요청 성별·연령집단·지역·기간을 포함합니다. 요청 집단과 실제 자료 모집단은 동등하다고 가정하지 않습니다. 명백히 대상이 다른 현행 정책은 후보에서 제외하도록 지시하며, 이는 모델 기반 적합성 판단이므로 독립 평가가 필요합니다. 지역 업무의 남은 호출이 5회 이상이면 2회를 설계 판단용으로 남깁니다. 유사사례 도구는 부분 문자열 검색이므로 설계자는 욕구에 맞는 단일 핵심어로 조회하고, 반환된 원문에서 대상 차이를 검토합니다.

유사사례는 검색 결과 중 최대100건에서 제목·요약의 검색어 및 대상 연령 단어를 우선하여 상세 최대5건을 조회합니다. 이는 ‘관계 법령’처럼 무관한 문구가 포함된 앞쪽 정책만 조사하는 문제를 줄이기 위한 단순 정렬이며, 의미 검색·자격 검증·대표 표본을 뜻하지 않습니다. 검색 범위·남은 페이지·정렬 기준을 결과에 보존합니다.

정책 후보의 대상 적합성 설명은 현재 자유문장이며, 서버의 정확 인용 검증은 정책 식별과 출처만 검증합니다. 모델이 대상 조건을 제대로 판단했는지는 독립 후보 라벨로 별도 평가해야 합니다. 새로운 구조화 필드만 추가해 이 판단을 검증한 것으로 간주하지 않습니다.

담당자 확인 필요 상태의 보고서는 즉시 승인할 수 없습니다. 콘솔의 ‘담당자가 수정본 작성’에서 확인 과제·원문을 검토하고 ‘수정본 검토 상태’를 ‘근거 검토를 마친 정책 초안’으로 선택해 사유와 함께 새 버전으로 저장합니다. 서버가 원문·공백 계약을 다시 검증하며 이전 상태는 이력에 남습니다. 저장 후에도 별도의 정책안 검토 승인이 필요하고, 자원 배정·예산·시행 승인은 발생하지 않습니다.

## 동별 세 정책 대안의 조사·설계 흐름

Supervisor가 지역 분석·통계 비교·자원 매칭의 미충족 필요를 정책 설계자에게 전달합니다. 설계자는 기존 후보 유무와 관계없이 미충족 필요를 우선한 최대 3개 주제로 `policy_analogues` 도구를 호출합니다. 한글 대상 집단을 전달하고 지원 내용·대상·선정 기준을 확인합니다. 조회 결과와 실패는 owner별로 저장해 반복 실행 시 재사용합니다. 이 도구의 지원 관할 밖 사례와 인구 유사성은 검증되지 않습니다.

작성 입력에는 조사한 원천 중 최대 3개의 상세 미리보기를 전달하고, 전체 조회 원문은 저장합니다. 모델은 지역 관측→원 정책의 정확한 요소 인용→지역 차이→현지 변경→담당 역할·운영 순서→기준선·비교·관측 기간·성공/중단 기준을 작성합니다. 서버는 출처 ID·지역 근거 ID·원문 인용 일치를 검증합니다. 원문 검증은 제안 효과나 의미상 타당성 판정이 아닙니다.

지역 근거, 제목 이상의 공식 정책 인용과 그 변경안, 구조화 평가 계획이 있어야 `structured_draft`로 표시합니다. 하나라도 부족하면 `needs_design_review`이며, 3개가 생성됐다는 사실을 맞춤 정책의 품질 통과로 해석하지 않습니다. 모델/자료/예산 실패 시 남는 기본 구상안은 현장 확인용으로 구분합니다. PDF·Word에도 같은 비교·변경·검증 항목이 포함됩니다. 이전 저장 보고서는 재작성하지 않으며 새 버전 생성 시 새 계약을 적용합니다.

세 개의 상세 정책안은 기본 짧은 응답 한도(1024토큰)에 잘릴 수 있어 `POLICY_DESIGN_MAX_OUTPUT_TOKENS`를 별도로 사용합니다(기본8192, 최대8192). 이 한도는 API 요청과 호출 전 비용 예약에 동일하게 적용됩니다. 총액·실행별 예산·호출 횟수 상한은 유지하며 부족한 경우 구상안으로 표시합니다. 다른 에이전트의 출력 한도는 바꾸지 않습니다.
