# 배포 준비 상태와 검증 관문

저장소에는 이제 Vercel FastAPI 진입점, UI 빌드, 같은 origin의 정적 프런트/API 구성이 있습니다. 실제 Vercel Preview 배포는 아직 검증되지 않았으며, SQLite·파일·BackgroundTasks의 durable 실행도 지원하지 않습니다. 설정 및 환경변수는 [Vercel 설정 안내](vercel-deployment.md)를 참고하세요.

## 확인된 플랫폼 조건

2026-10-22 공식 문서 확인 기준입니다. 실제 프로젝트 요금제·런타임 설정에서 다시 확인해야 합니다.

- FastAPI는 `app` 인스턴스를 노출하는 진입점을 지원하고, `public/` 정적 파일을 CDN에서 제공합니다. 현재 앱은 `create_app()` factory입니다. [FastAPI 안내](https://vercel.com/docs/frameworks/backend/fastapi)
- Python의 일반 함수 번들은 압축 해제 후 500 MB 제한이며 불필요한 파일을 명시적으로 제외해야 합니다. 로컬 가상환경 크기로 실제 배포 번들 크기를 판정하지 않습니다. [Python 런타임](https://vercel.com/docs/functions/runtimes/python)
- Fluid Compute의 기본 최대 시간은 Hobby 300초, Pro/Enterprise는 일반 최대 800초입니다. 스트림 응답 시간도 이 제한에 포함됩니다. 계정별 확장 설정은 별도입니다. [함수 제한](https://vercel.com/docs/functions/limitations)

## 현재 앱에서 반드시 바꿔야 하는 부분

| 영역 | 현재 구현 | 배포 완료 기준 |
|---|---|---|
| 이벤트·검토·LLM 비용 | `backend/events.py` SQLite 연결; 여러 모듈이 같은 연결에서 SQL 실행 | 공유 영속 DB, 트랜잭션·멱등·비용 상한·동시 검토 충돌 보존 |
| 그래프 상태 | `backend/graph.py`의 SQLite 체크포인터와 프로세스 내 잠금 | 인스턴스 간 체크포인트·작업 소유권·승인 재개 보장 |
| 정책 원문 | `backend/policy/service.py`의 별도 SQLite 스냅샷 | 전체 수집 성공 시 원자적 교체, 실패 시 이전 스냅샷 보존 |
| 평가·합성 시나리오 | `runtime/quality*` 파일, 동결 입력·보고서 및 미래 시나리오 파일 | 영속 DB/객체 저장소, 해시·버전·쓰기 원자성 보존 |
| 비동기 작업 | FastAPI `BackgroundTasks` | 요청 종료·시간 초과·cold start에도 실행 재개와 실패 이력 유지 |
| 관찰 스트림 | 종료 시간 없는 SSE, 이벤트 커서 | 함수 한도 안에서 연결 종료·커서 재접속; 중복 수신 안전 |
| 웹 경로 | Vite 개발 프록시 | 같은 origin의 API 라우팅과 SPA 직접 링크·새로고침 검증 |

Vercel 진입점은 쓰기 가능한 `/tmp`를 사용하지만, 이는 공유 영속 저장소가 아닙니다. 인스턴스 교체·cold start 시 데이터가 사라지거나 다른 인스턴스에서 보이지 않을 수 있습니다. DB URL 하나를 추가하는 변경만으로 완료되지 않습니다. SQL의 SQLite 전용 구문·로컬 파일 평가 경로·MCP 하위 프로세스까지 호출 경로를 전부 검증해야 합니다.

## 남은 PR 순서

1. **V0 계정·기술 검증**: Vercel 로그인/프로젝트 연결, Preview에서 최소 Python 진입점·정적 파일·API 경로·실제 번들 확인. DB 제공자·지역·풀링 연결과 계정 시간 제한 확정.
2. **V1 진입점과 정적 배포**: factory를 재사용하는 진입점과 경로 설정. 쓰기 API의 영속성이 준비되기 전에는 완성 데모로 공개하지 않습니다.
3. **V2 영속성**: 이벤트·체크포인트·정책·평가/합성 파일을 함께 이전. 재배포 후 조회, 동시 실행·승인 충돌·중복 요청·비용 집계를 검증합니다. sample/local 양쪽 비용 장부를 합산하는 현재 예산 범위도 보존합니다. 로컬 SQLite 경로는 유지합니다.
4. **V3 작업과 스트림**: 지속 가능한 작업 실행 및 SSE 재접속. 현재 시작 시 복구가 모든 pending/running 평가 작업을 실패 처리하므로 다중 인스턴스에서는 다른 인스턴스의 실행까지 중단된 것으로 오판할 수 있습니다. 작업 소유권·임대 만료를 확인하는 복구로 변경하고, 실제 함수 종료·cold start에서 재개 테스트를 수행합니다. 평가의 호출 시간 합계와 SSE 버퍼링도 측정하며 한도를 넘는 작업은 지속 실행 경로로 분리합니다.
5. **V4 공개 범위**: 접근 제한, sample/fake/stub 고정, 비밀값과 로컬 자료의 빌드 제외, 보존/삭제/롤백 절차. 실제 기관 전달과 유료 호출은 초기 공개 데모에서 제외합니다.
6. **V5 Preview 검수**: 실제 URL에서 지역 분석→통계→매칭→정책 설계 보고서→검토, 남녀 비교, 평가 화면, 모바일·키보드 E2E. 이 단계까지 통과해야 배포 완료입니다.

V0에서 인증된 프로젝트와 영속 저장소가 확인되지 않으면 후속 배포 성공을 주장하지 않습니다. 사용자 환경에서 Vercel 로그인 및 프로젝트 연결, 사용할 영속 DB 연결이 필요합니다. 비밀값은 문서·PR·브라우저 번들에 넣지 않습니다. 그 전까지 로컬 구현과 테스트 결과를 배포 검증과 구분합니다.
