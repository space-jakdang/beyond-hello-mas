# 지역 정보 입력 계약

지역 프로필은 고립 지수와 별도로 읽는 인구·가구·주거 집계 문맥이다. 개인 자격·고립 인원·서비스 수요 분모가 아니다.

현재 구현은 입력 검증·지역 코드 대조·관측 식별자·비교 조건과 KOSIS 조회 서비스·프로필 API·준비 상태 진단이다. 새 `policy_context_version=regional-policy-2` 지역 업무는 실행 시작 시 프로필을 수집·고정하고 통계·정책 검토·조건부 설계에 전달한다. 새 지역 업무 화면은 이 계약을 기본 선택한다. 저장된 이전 업무 계약과 결과는 유지한다. 합성 응답 검사는 실제 제공자 수집 성공이나 정책 품질을 증명하지 않는다.

사용자가 이미 발급한 인증키가 KOSIS임을 확인하여 최초 제공자를 KOSIS 하나로 선택했다. 서버 환경변수는 KOSIS_API_KEY이며 별도 secret은 필요 없다. 정부24 인증과는 별도다.

| 항목 | 우선 원천 | 검증 상태 |
|---|---|---|
| 인구·가구·주택 | KOSIS 인구총조사 표(101/DT_1IN1502) | 공식 표/인자 정의 확인, 실제 인증 응답·원래 8자리 코드·연주기 A·T100/T200/T310 항목명 확인 |
| 일반가구·1인가구·고령/청년 구성 | 101/DT_1JC1502, DT_1IN1503 | 공식 분류/항목 확인. 1인가구 비중은 일반가구 분모. 청년은 19세+20–24+25–29+30–34의 정확 합만 사용. 실제 인증 수치 대조 진행 중 |
| 기존 사업·신청 경로 | 기존 정부24/지역 카탈로그 | 등록 정보이며 시설 수·정원·이용량이 아님 |

자료별 값·단위·모집단·연령·성별·지역 수준·제공자 코드/버전·기준연도·조회/발표시각·원문/해시·누락 사유를 보존한다. 억제/누락 값은 0으로 바꾸지 않는다. 비교는 같은 지표·정의·기간·모집단·지역 수준/버전 안에서만 허용한다. 시군구 값을 동의 관측으로 복제하지 않는다. 현재 조회한 자료의 과거 당시 가용성은 발표시점이 확인되지 않으면 미검증이다.

현재 경계는 2025-07-01의 8자리 통계동 코드다. 신사동 11230510과 개포3동 11230511을 자르면 충돌한다. 따라서 제공자 지역 목록을 정규화하고 부모 관할·동 이름이 유일하게 일치할 때만 원래 제공자 코드를 보존한다. 서로 다른 코드 체계는 별도 검증된 연결 없이는 미확보로 둔다. parent_and_name_only는 경계의 공간적·시계열적 동일성을 확인했다는 의미가 아니다. 분동·코드/이름 충돌은 실패시킨다.

[통계자료 공식 안내](https://kosis.kr/openapi/devGuide/devGuide_0201List.do), [통합검색 안내](https://kosis.kr/openapi/devGuide/devGuide_0701List.do). 고정 HTTPS API만 호출하고 키는 원문 URL·로그·모델 입력·프런트에 포함하지 않는다. 실제 키가 없는 검증은 생성 fixture/실패 경로 검증이며 실제 통계 수집 성공이 아니다.

## 서버 설정과 조회

서버 환경변수 `KOSIS_API_KEY`에 발급된 사용자인증키 하나를 등록한다. `REGIONAL_REFERENCE_YEAR`의 기본값 2020은 문서에서 동 단위 제공을 확인한 기준연도이며 최신 자료라는 의미가 아니다. 실제 키를 연결한 뒤 해당 표의 수록 기간과 제공 항목을 대조하여 운영 기준연도를 선택한다.

`GET /analysis/regional-context?sgg=11230&dong_cd=11230510&reference_year=2020&as_of=2026-10-24`는 자료·출처·기준시점·미확보 항목을 반환한다. `sample`에서만 명시적 생성 fixture를 사용하고, `local`의 키 부재/조회 실패/지역 불일치는 `unavailable`로 남긴다. 누락 원인은 비밀값/원래 요청 URL을 포함하지 않는 코드다. 미완료 자료도 조회 API에서는 상태를 읽을 수 있으며 정상 자료인 것으로 표시하지 않는다.

캐시는 서버 실행 저장 경로의 SQLite에 저장하며 지역·연도·경계와 쿼리 버전별로 분리하고 최대 하루 재사용한다. 저장 응답의 해시를 확인하며 변조된 캐시는 사용하지 않는다. 인구·가구 정의가 다른 원천을 같은 값으로 합치지 않는다. 새 계약은 실행과 배치 owner별 스냅샷을 고정하며 재개 때 재조회로 바꾸지 않는다. Vercel `/tmp`의 캐시는 영속 저장이 아니며 소실 시 다시 조회한다.

해시 검사는 우발적인 손상을 탐지하며 서버 파일을 임의로 수정할 수 있는 공격자에 대한 인증 수단은 아니다. 캐시 키·표·기간도 재검증하고 잘못된 캐시는 폐기하여 다음 조회에서 복구한다. 프로필 조회 결과의 요청·시각·상태·출처 해시 이력은 최근 500건까지 서버에 보존하며 인증키와 원래 요청 URL은 저장하지 않는다. 일부 표가 실패해도 검증된 다른 표의 관측은 유지한다.

각 표의 원래 8자리 코드와 이름은 요청 관할의 경계 목록과 대조하고, 요청하지 않은 분류는 관측으로 사용하지 않는다. 손상된 선택 정책 캐시는 통계 관측의 조회 실패로 전파하지 않는다. 조회 이력을 읽을 수 없으면 준비 상태를 미확인으로 유지한다.

`/readiness.regional_context`는 키 설정 여부와 자료 조회 상태를 구별한다. `not_checked`는 실제 자료 준비 완료가 아니다. 기존 `ready`는 기존 지역 분석/자원 목록 준비의 의미를 유지한다.

설정된 기준연도의 최근 하루 내 조회가 있으면 마지막 요청 지역의 `ready`/`partial`/`unavailable`과 요청·시점을 함께 표시한다. 이는 모든 동의 준비 상태를 뜻하지 않는다. 프로필의 `resources`는 관할에 맞는 기존 카탈로그 최대 10건과 저장된 정부24 사업 최대 5건을 출처와 함께 연결하며 전체 건수·목록의 수집 상태를 구별한다. 이 조회는 정부24 목록을 새로 수집하지 않는다.

지역 통계는 `total_households`(가구_계)와 `general_households`(일반가구_계)를 구별한다. 1인가구의 분모는 일반가구이며 외국인가구·집단가구를 섞지 않는다. 고령·청년 인구는 성별 합계를 한 번만 사용한다. 연령표 합계와 총인구표의 동일 동·연도 값이 일치할 때만 같은 인구 모집단으로 비율 계산을 허용한다. 모든 측정값에 표/항목/분류 코드를 보존한다. 인구밀도·평균연령은 아직 미확보이며 이 때문에 프로필 상태는 partial일 수 있다. 일부 유효 수치를 활용하되 missing은 0이나 준비 완료로 표시하지 않는다.

## 통계 검토

인구·가구·주거 집계는 고립 지수와 별도로 해석한다. 1인가구 비중의 분모는 같은 정의의 일반가구, 고령·청년 비중의 분모는 같은 정의의 총인구다. 원천·기간·모집단·성별·지역 수준이 다르거나 분모가 0이면 계산하지 않는다. 통계 분석가의 메모는 관측 fact ID, 정책 검토 의미, 확인할 가설, 부족한 증거를 구별한다. 모델에 제공하지 않은 사실은 인용할 수 없고, 조회한 비교 지역의 근거는 실제 도구 관측에서 제공된 경우에만 인용한다. 비교는 집계 규모의 기술 통계이며 위험 순위·원인·서비스 수요가 아니다.

간소화한 모델 입력에도 제공자 지역 코드·경계 버전·표·항목·분류·게시 시점과 미확보 사유를 남긴다. 게시 시점이 없으면 과거 당시 가용성을 확인한 것으로 해석하지 않는다. 계산·스키마·조회/재검토 제어의 생성 fixture 검사와 실제 모델 해석 품질 평가는 구별한다.

과거 첨부 프로필에 일반가구 지표 자체가 없을 때만 같은 정의의 `total_households`를 호환 분모로 사용한다. 일반가구 지표가 존재하지만 missing인 경우에는 대체하지 않는다. 현재 KOSIS 프로필은 일반가구를 별도로 제공하므로 이 호환 경로로 서로 다른 가구 모집단을 합치지 않는다.

동별 비교는 관측 지역 코드가 서로 다른 동 자료만 사용한다. 구 단위 문맥은 원래 지역 수준과 함께 보존하되 동별 비교에서는 제외한다. 같은 구 통계를 여러 동에 첨부해도 독립된 동 관측으로 세지 않는다.

## 필요별 기존 정책 검토

기존 PolicyAgent가 첨부된 지역 프로필·통계 메모·필요별 검토 요건을 읽고 기존 사업 활용, 확인된 중요 공백의 보완, 완료된 검색 범위 안의 신규 설계 검토, 추가 근거 확인으로 구분한다. 새 계약에서는 Supervisor가 자동 전달하고 설계로 연결하며, 화면과 PDF·Word 보고서에 같은 고정 근거와 대응 판단을 표시한다. 개인 소득 자격·잔여 정원 미확인만으로 새 정책을 만들지 않으며 검색 실패를 정책 부재로 해석하지 않는다.

서버는 카탈로그 후보를 기존 관할·날짜·연령·필요 필터로 다시 검사한다. 정부24 후보는 같은 서비스 ID의 공식 지원조건에서 성별·연령을 확인하고 등록기관 관할과 요청 지역을 대조한다. 조건 누락은 중요한 정보 미확인이며, 일부 연령만 해당하는 사업을 집단 전체의 활용안으로 확정하지 않는다. 명시된 종료일이 지났거나 요청 시점보다 뒤에 수정된 자료도 활용 충분으로 표시하지 않는다. 자유 서술형 요건의 의미·현장 효과는 별도 검토가 필요하다.

[정부24 공식 명세](https://infuser.odcloud.kr/api/stages/44436/api-docs?1684891964110)의 `supportConditions`는 JA0101/JA0102를 남성/여성, JA0110/JA0111을 대상연령 시작/종료로 정의한다. 실제 API 인수와 모델 판단 품질은 합성 계약 검사와 구별한다. 확인한 신청 방법·기한·문의처·기관은 원문에서 복사하며 없는 정보는 미확인으로 남긴다. 안내안은 담당자 검토용으로 외부 게시·문자·메일 발송을 수행하지 않는다. 외부 `/scenarios/run` 요청에서는 서버 전용 지역 조사 입력을 직접 주입할 수 없다.

단건·묶음 상세 조회 모두 공식 대상 조건을 모델 입력에 보존한다. 서버에서 중요한 조건 불일치가 확인된 필요만 `needs_evidence`로 보류하며 다른 필요의 유효한 검토는 유지한다. API·모델·예산·입력 오류로 종료한 경우에도 필요별 보류 결과와 종료 사유를 남긴다. 원문 인용 자체가 잘못된 응답은 검토 결과 전체를 확정하지 않는다.

검색 완료는 각 페이지가 조회 당시 성공·최신·완전 상태였고 동일한 목록 스냅샷을 사용한 경우에만 인정한다. 이후 갱신 성공으로 이전 실패 검색을 완료 처리하지 않으며, 상세 재조회가 실패하면 과거 성공 기록을 최신 확인으로 사용하지 않는다. 중복 동 프로필은 거절하고 실제로 검증해 모델에 보여 준 관측 근거 ID만 인용할 수 있다. 해석할 수 없는 명시 날짜는 해당 필요의 중요 정보 미확인으로 남긴다.

새 조사 결과의 추천 목록은 `reference_only` 참고 후보이며 현지 이용 가능 판정은 검증된 필요별 안내에서만 읽는다. 검토 완료는 필요별 결과로 판단하므로 기존 사업 안내가 있으면 추천 슬롯이 비어 있어도 완료할 수 있다. 활용·보완 결과의 안내 초안은 확인한 공식 필드를 복사하며 홍보 경로는 별도 제안으로 표시한다. 개인 자격·접수·정원 확인과 담당자 검토가 필요하고 실제 발송은 하지 않는다. 카탈로그의 수집일과 기준일은 한국 시간의 날짜로 비교한다.

## 조건부 지역 정책 설계

`policy_context_version=regional-policy-2` 경로는 `pinpoint-1` 설계 계약을 선택한다. 단일 업무와 배치 부모가 같은 동별 설계 함수를 사용하며, 새 화면은 두 자료 버전에서 이 정책 계약을 지정한다. 이전 버전의 고정 세 유형·항상 세 개 계약과 저장 결과는 유지한다.

`reuse_existing` 또는 근거 부족이면 대안을 생성하지 않는다. 검증된 보완·신규 설계 필요에만 서로 다른 운영 선택 3개를 만들며, 선택한 필요·집단별 문제 근거와 관측된 지역 사실, 실제로 보여 준 정책 원문의 지원·대상·조건 인용, 운영 차이와 평가 계획을 요구한다. 필요한 원문은 같은 실행의 고정 자료에서 한 번 추가 조회할 수 있으며 실패·예산 부족을 일반 템플릿 성공으로 채우지 않는다. 전체 원문과 18개 정의 필드는 저장하고 모델 입력만 기존 바이트 한도 안에서 압축한다.

원천 연령 12집단을 지원하며 v4의 유효한 판정 단계는 연속 점수가 없어도 관측으로 보존한다. 보류·근거 부족 단계는 설계 근거로 사용하지 않는다. 동별 owner 세트는 재요청 시 같은 저장 결과를 반환하며 최초 저장과 재현 모두 요청 범위를 확인한다. 기관은 공식 출처의 등록기관으로만 연결하고 참여 협약·운영 인력·장소·예산·정원·효과는 확인된 사실로 표시하지 않는다. 생성 fixture의 구조 검사와 실제 모델의 지역 특화·대안 다양성 평가는 구별한다.

## 고정 입력과 실행 범위

기존 `POST /scenarios/run`의 지역 monthly payload에 `workflow_version`과 별도로 `policy_context_version=regional-policy-2`를 지정한다. `POST /regional/batches`도 같은 선택 필드를 받는다. `regional-workflow-1`은 기존 자료, `regional-workflow-2`는 schema-4 원천 연령·카드 자료를 뜻하며 정책 계약 이름으로 재사용하지 않는다. 기준연도 기본값은 검증된 2020을 유지한다.

단일 실행과 배치는 요청 owner별 지역 프로필을 고정하고, 배치 자식들은 그 프로필·원천·카탈로그를 공유한다. 자식은 분석·탐색만 수행하고 부모가 선택 집단의 검토를 동별 세트 하나로 모은다. 다른 관할·시점·동 목록·자료 모드로 같은 owner를 재사용하면 거절한다. 실패·미관측 집단은 누락으로 남고 판정 단계·카드 신호만으로 서비스 필요를 만들지 않는다.

통계 모델에는 최대 세 동의 프로필과 열두 비교를 전달하고 누락된 동·비교 수를 표시한다. 한 자식의 심층 정책 조사는 분석 우선 동 하나부터 수행하며, 조사하지 못한 필요는 확인 보류로 남긴다. 전체 지역의 정책을 모두 검토했다는 의미가 아니다. `regional-research-2`는 검토 필요별 실제 `source_bands`·연령 구간을 정책 대상과 대조하며 표시 집단 연령으로 관측 범위를 바꾸지 않는다.

잘린 정책 필드는 `policy_field`로 같은 실행의 최신 고정 상세에서 읽는다. 이후 상세가 실패하거나 바뀌면 과거 필드는 확정 근거로 쓰지 않는다. 인용은 실제로 보여 준 필드에 한정하고 원문 전체·조회 이력은 보존한다. 기존 호출·비용 한도와 단계별 120초 종료 시각을 사용하며, 진행 중 호출은 기존 timeout을 따른다. 한도를 넘으면 추가 확인 사유와 빈 대안 목록을 남기고 기본 구상안을 성공으로 채우지 않는다.

배치의 정부24 조회는 같은 owner의 최초 응답을 공유하고 단건·묶음 상세를 정책 ID별 같은 원문에 연결한다. 과거 자식 결과에서 동일 ID의 원문·대상 조건 충돌이 발견되면 섞어서 설계하지 않고 해당 동을 보류한다. 취소가 저장된 뒤에는 새 유료 호출을 예약하지 않으며, 진행 중 조회가 끝난 뒤 다음 정책·참고 사례 조회도 시작하지 않는다. 전체 출처와 보류 이유는 남긴다.

과거 결과의 정부 정책 안내에 고정된 공식 대상 조건을 대조할 근거가 없으면 동일 출처로 간주하지 않고 `policy_source_snapshot_unverifiable`로 보류합니다. 정책 본문이 같더라도 공식 조건의 일치를 뜻하지 않습니다.

## 화면과 보고서

새 지역 업무의 통계 근거 탭에서 고정된 지역 사실과 출처·정의·기준연도·지역 코드·경계 버전·발표/조회 시각·누락 사유를 확인한다. 분석가의 정책 검토 의미와 확인할 가설은 관측값과 구별한다. 선택한 동 밖의 근거는 해당 동에서 확인하도록 안내한다.

자원 제안의 지역 정책 대응안은 필요별 기존 활용·보완·신규 설계·추가 확인을 나눈다. 기존 사업의 대상·신청 방법·기한·문의처와 저장된 담당자 검토용 안내 초안을 제공하며 실제 발송·게시하지 않는다. 새 대안은 사용한 지역 사실로 이동하는 링크, 운영 접점, 원 정책과의 차이와 검증할 조건을 제공한다. 대안이 없어도 활용안·보류 사유를 PDF와 Word로 내려받을 수 있다. 다운로드는 화면의 현재 지역 필터나 최신 통계가 아닌 지정한 저장 버전·검토 revision을 사용한다. 이전 세 대안 보고서의 조회·수정·검토도 유지한다.

모델 입력은 지역 사실의 18개 정의 필드를 유지하며 바이트 한도에 맞춰 전달할 동의 상세 문맥 수를 조정한다. 나머지 동의 목록과 미표시 범위를 명시하고 통계 도구로 추가 확인한다. 통계 판단 입력의 짧은 지역 사실 ID는 검증 전에 원래 식별자로 복원하며 저장된 프로필·도구 원문은 바꾸지 않는다.
