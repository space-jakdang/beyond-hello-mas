# 실제 지역 서비스의 단일 서버 운영

이 구성은 비공개 대회용 단일 Linux 서버와 영속 볼륨을 사용합니다. SQLite·체크포인트·정책 캐시·평가/미래 결과·보고서·비용 장부를 함께 보존합니다. 서버리스 임시 디렉터리와 다중 worker는 이 구성에 포함되지 않습니다. 기존 Vercel 배포가 이 서버로 자동 전환되는 것은 아닙니다.

선행: `scripts.runtime_package`와 [입력 패키지 계약](runtime-inputs.md)이 포함된 코드 버전, 사용 범위를 확인한 비공개 패키지, 영속 볼륨, HTTPS와 접근 제한 설정. 입력 검증 성공은 외부 API 키·정책 적합성·볼륨 영속성을 증명하지 않습니다.

## 배치

- `/opt/beyond-hello/<code-version>`: 코드, `uv sync --frozen`으로 설치한 `.venv`, `npm --prefix frontend ci` 및 `npm --prefix frontend run build` 산출물. UI와 API를 같은 서버에서 제공하는 것이 기본안입니다.
- `/srv/beyond-hello/inputs/<input-version>`: 검증 완료 입력. 읽기 전용 권한을 부여하고 정적 웹 루트 밖에 둡니다. 입력 경로에는 심볼릭 링크를 쓰지 않습니다.
- `/var/lib/beyond-hello`: 서버 사용자만 읽고 쓰는 영속 경로. 로컬 DB를 복사하지 않고 앱이 새 저장소를 생성합니다.
- `/etc/beyond-hello/service.env`: 키/모델/가격/예산을 포함한 운영 환경 파일. 저장소의 `.env`와 별도이며 실제 값을 로그나 PR에 남기지 않습니다.

관리자가 `beyond-hello` 사용자와 위 경로/권한을 준비한 후 `deploy/beyond-hello.service`를 설치합니다. 예제 경로는 실제 배치와 일치시킵니다. 실행 명령은 다음과 같습니다.

```sh
python -m scripts.serve_private --port 8000
```

시작 전 파일 목록·해시·스키마·경계와 반입 확인 상태를 검사합니다. pending 상태는 로컬 패키지 생성/검증까지 가능하지만 이 운영 진입점은 시작하지 않습니다. 같은 실행 디렉터리를 사용하는 두 번째 서버는 파일 잠금으로 거부합니다. 기본 uvicorn 명령으로 이 진입점을 우회하여 두 번째 프로세스를 실행하지 마세요.

서버는 loopback에만 바인딩합니다. `deploy/nginx-private.conf.example`을 HTTPS server 블록에 넣어 UI·API·SSE·보고서 다운로드 전체에 같은 인증을 적용합니다. 서비스 포트를 외부에 직접 개방하지 않습니다. 접근 제한은 담당자별 감사 권한 체계와는 다릅니다. 다수 기관에 배포하려면 별도 계정·권한 설계가 필요합니다.

Vercel 프런트를 유지하려면 이 API로 same-origin 프록시·인증 전달·SSE를 추가 검증해야 합니다. 프런트만 옮기고 기존 `/api`가 임시 Vercel 백엔드를 계속 호출하는 상태를 완료로 보지 않습니다. 최소안은 여기서 빌드한 UI까지 함께 제공합니다.

## 재시작·교체·복구

1. 새 입력 버전을 별도 경로에 적재하고 `python -m scripts.runtime_package verify <root>`로 검사합니다. manifest의 확인 기록은 실제 반입 확인에 근거해야 합니다.
2. 새 요청을 막고 진행 중 작업 상태를 기록한 후 서비스를 정지합니다. 정지된 상태에서 전체 영속 디렉터리를 비공개 백업합니다. 실행 중 SQLite 본체만 복사하면 WAL·체크포인트·캐시를 잃을 수 있습니다.
3. 환경 파일의 INPUT_ROOT와 코드 경로를 준비된 버전으로 바꾸고 재시작합니다. 이전 코드/입력 버전과 백업을 보존합니다. DB 스키마 변경이 있으면 코드만 되돌리지 말고 호환성 또는 정지 시점 전체 백업 복구를 검토합니다.
4. 인증된 `/health`, `/readiness` 및 실제 이전 run/승인 대기/보고서 조회를 확인합니다. `ready=true`와 별개로 모델 키·외부 API·재시작 보존을 검증합니다.
5. 실패하면 새 요청을 막고 정지한 뒤 이전의 호환되는 코드·입력·저장소 상태로 복구합니다. 복구 후 중복 요청과 승인 상태를 확인합니다.

기존 graph recovery는 저장된 체크포인트에서 실행을 재개하며 평가 작업 등은 중단 상태로 기록될 수 있습니다. 외부 모델 호출 직후 프로세스가 죽으면 동일 호출이 재시도될 가능성이 있습니다. 파일 잠금은 중복 서버를 막지만 외부 호출의 exactly-once나 모든 작업의 자동 복구를 보장하지 않습니다. 진행 중 유료 호출을 포함한 장애 주입 검증은 별도 운영 관문입니다.

## 확인 목록

- 실제 읍면동과 경계 연결, 성별/집단 전체, 실측 기간·결측 표시.
- 지역 업무→통계→정책 후보/대안→PDF/Word→담당자 검토 대기. 실제 승인·배분은 실행하지 않음.
- 재시작/재배포 후 기존 run·비용·검토 상태 유지, SSE 재접속, 직접 링크 새로고침.
- 비인증 UI/API/보고서 차단, 원자료·DB·키 다운로드 불가.
- 기본 입력 해시가 미래 합성/평가 실행 후에도 그대로이고 결과 저장 영역이 분리됨.
- 원천 입력·정책 캐시·백업·배포 사본의 목록/관리자/보존 조건 기록, 대회 종료 후 안내에 따라 폐기.

이 문서와 예제 설정은 서버 구축 산출물입니다. 특정 호스팅 계정 연결·도메인·TLS 발급·실제 배포와 운영 검수 완료 기록은 아닙니다. 방법론과 화면 변경은 해당 기능 PR을 통합한 코드 버전으로 다시 검증합니다.

개발 환경의 프로세스 재시작 회귀는 `uv run pytest tests/test_private_service_restart.py`로 실행합니다. 생성한 시험 자료로 실제 진입점을 시작하고 지역 업무를 검토 대기까지 실행한 다음, 서버를 종료·재기동해 저장된 검토 결과와 입력 불변성을 확인합니다. 외부 키·실제 원자료·유료 호출을 사용하지 않으므로 실제 Linux 배포와 외부 호출 중 장애 복구는 별도 검증해야 합니다.

## Render에서 실행 기록 보존

[`deploy/render.yaml`](../deploy/render.yaml)은 UI와 API를 함께 제공하는 Python 웹서비스 한 개와 1GB 영속 디스크를 정의합니다. Blueprint 생성 시 파일 경로를 `deploy/render.yaml`로 지정하며 빌드·실행 기준 디렉터리는 저장소 루트입니다. [유료 디스크](https://render.com/docs/disks)는 재시작·재배포 후 같은 파일을 보존합니다. 서비스 생성은 유료이며, 실제 계정 연결·과금 승인·검증이 끝나기 전에는 운영 주소를 전환하지 않습니다.

- 시작 명령은 `.venv/bin/python -m scripts.serve_hosted`입니다. 기존 `prepare`의 입력 검증·반입 확인·단일 프로세스 잠금을 재사용하며, Render에서는 `RUNTIME_STORAGE_ROOT`가 실제 마운트 지점이 아니면 시작을 거부합니다. `/var/lib/beyond-hello`의 이벤트·체크포인트·캐시·평가·보고서·비용 기록을 함께 보존합니다. 디스크 경로·`EVALUATION_ID`를 바꿔 기존 비용 장부를 초기화하지 않습니다.
- `RUNTIME_INPUT_PACKAGE`에는 확인된 최소 패키지의 인코딩 값을 서버 환경변수로 등록합니다. [입력 패키지 연결 절차](vercel-deployment.md#기존-지역-자료를-배포-기본값으로-연결)의 생성·확인 계약을 재사용합니다. 고정 관측 입력은 매 시작 때 복원하며 실행 기록은 영속 디스크에 남습니다. 기존 Vercel 인스턴스에서 이미 사라진 실행을 복원하지는 않습니다.
- `PRIVATE_HTTP_USER`와 24자 이상의 `PRIVATE_HTTP_PASSWORD`가 없으면 시작하지 않습니다. Blueprint는 사용자명 `reviewer`와 임의 비밀번호를 생성합니다. 담당자는 Render의 서버 환경 설정에서 비밀번호를 확인해 HTTPS 주소의 브라우저 인증 창에 입력합니다. 화면·API·SSE·다운로드·문서 모두 인증을 요구합니다. 배포 확인용 `/healthz`만 본문 없는 200을 반환하며 자료·실행 상태를 공개하지 않습니다. Render의 HTTPS 입구를 통해서만 접속합니다.
- 첫 배포는 `LLM_MODE=fake`로 재시작·인증·다운로드를 점검합니다. 실제 운영 전 기존 비용 장부를 이전하거나 이미 사용한 비용과 잔여 예산을 대조한 뒤 승인된 범위에서 `live`로 전환합니다. 새 서버의 빈 DB를 기존 누적 비용이 0이라는 근거로 사용하지 않습니다. OpenAI·정부24 키와 모델·가격·실행별/누적 예산은 비공개로 등록하고 예산을 자동 증액하지 않습니다. 빌드 중에는 원자료·키를 소스나 프런트엔드 산출물로 복사하지 않습니다. `render.yaml`의 `sync: false`는 운영자가 등록할 비밀값 자리입니다.
- 자동 배포는 꺼져 있습니다. 첫 배포 및 교체 전에 입력과 디스크 설정을 점검하고, 진행 중인 업무가 끝난 뒤 재배포합니다. 서비스 종료 유예는 120초이며 강제 종료 시 모델 호출이 중복될 가능성은 위 복구 제한을 따릅니다. 한 디스크를 여러 독립 인스턴스에 복사해 병렬 운영하지 않습니다.

인수 검사는 인증된 요청으로 지역 업무 생성→`/runs/{id}/overview` 조회→검토 대기→서비스 재시작/재배포→같은 실행·트레이스·승인·보고서 재조회 순서입니다. 비인증 요청은 `/healthz`를 제외하고 401이어야 합니다. 로컬 회귀는 기존 private 진입점과 hosted 진입점 모두 같은 검토 기록을 보존하는지 확인합니다. Render의 실제 디스크·TLS·비밀 설정 확인은 해당 계정에서 별도로 실행합니다.

Vercel에서 `ready=true`는 관측 자료 준비 상태이며 실행 저장소 영속성을 의미하지 않습니다. 실행을 만든 인스턴스와 조회한 인스턴스의 임시 DB가 다르면 `404 run not found`가 발생할 수 있습니다. 운영 전환 후에는 새 상주 서비스의 UI/API 주소를 함께 사용하고, 이전 Vercel 화면에서 분석 요청을 계속 보내지 않도록 안내합니다.
