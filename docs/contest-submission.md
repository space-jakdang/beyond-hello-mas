# 제출 후보 설명과 재현 순서

이 프로젝트는 지역·인구집단의 관측 신호를 담당자의 우선 검토와 자원 조사로 연결한다. 지역 단계는 먼저 확인할 순서이며 개인의 고립 사실이나 임상 판정이 아니다. 구현된 협업이 단일 에이전트보다 유용한지는 별도 사람 평가로 판단한다.

## 제출 상태

공개 코드 후보와 대회 제출 완료는 구분한다. 현재 구현·검증할 수 있는 내용과 외부 확인이 필요한 내용은 다음과 같다.

| 항목 | 코드·자료 | 완료로 주장할 수 없는 내용 |
|---|---|---|
| 공식 요구와 증거 대조 | [1008판 대조표](contest-evidence.md) | 최신 공지·양식·마감 재확인 |
| 지역 데이터 근거 | [출처·민감도 검증](analysis-evidence.md) | 제공자 원자료에서 독립 재계산, 실제 고립 정답 정확도 |
| 공정 비교 기준 | [개발8/평가24 계약](agent-comparison.md) | 독립 라벨 검수, 실제 모델 우월성 |
| 에이전트 상호작용 | [checkpoint와 조회·수정](architecture.md) | 메시지 수·노드 수를 품질 향상으로 해석하기 |
| 정책 자원 조사 | [기존 worker로 위임](policy-tools.md) | 개인 자격·잔여 정원·실제 배정·모든 현실 정책 보장 |
| 사람 평가·채택 | [가림 평정과 paired 집계](agent-comparison.md) | 독립 평정·실제 모델 실행·담당자 과업 실증이 없는 채택 결론 |
| 개인 판정 | 기존 계약만 유지 | 신규 개인 판정 확장·고립 대상자 식별 |

live 평가 예산, 독립 검토자, 외부 원본 제출 권한과 공식 양식이 확인되기 전에는 제출 준비 완료로 표시하지 않는다. 이 문서는 코드 후보의 설명이며 외부 문의나 제출을 자동으로 수행하지 않는다.

## 발표 초안

1. **문제와 대상:** 관측은 강남·춘천의 지역 집단이다. 낮은 활동을 개인 고립으로 단정하지 않고 담당자의 확인 순서를 돕는다.
2. **데이터 근거:** 동별 지표와 시군구 주간 카드 신호의 공간·연령·기간이 다르다. 출처 대응표와 한계를 함께 표시한다. 월 없는 기간 집계를 월별 관측처럼 만들지 않는다.
3. **대응 흐름:** 결정적 도구가 숫자 단계를 계산한다. 분석자는 계획을 내고, 검토자는 부족한 근거를 요청한다. Supervisor가 허용된 조회를 수행하고 수정안·미해결 사항을 남긴다.
4. **자원 공백:** 검증된 카탈로그가 부족하면 정책 조사 후보를 별도로 반환한다. 후보의 자격·정원 확인과 최종 승인은 담당자의 일이다.
5. **평가와 반론:** 합성 예측, 절차 검증, 실제 모델의 계획 품질을 분리한다. 단일 에이전트에도 같은 조회·자기 검토 기회를 주고 실패·비용·지연을 포함해 비교한다. 실제 결과가 없으면 수치를 채우지 않는다.
6. **운영 제안:** 우선 지역 검토 지원으로 시험 운영한다. 데이터 갱신 주체, 원본 사용 권한, 사람 검토·기관 연계 책임을 정한 뒤 확대한다.

이는 2차 발표 구성 초안이다. 발표 시간 측정·외부 청중의 질의응답·독립 모의 심사 점수는 아직 없다. 공식 2차 기준의 내용·구성, 분석 설명력, 설득력, 발표·소통을 이 초안으로 모두 검증했다고 주장하지 않는다.

## 시연 3개와 해석

관찰 화면과 콘솔은 API 응답에 따라 바뀌는 대시보드다. PNG는 기록용이며 시연 자체가 아니다.

| 시연 | 실행 조건 | 확인할 화면·기록 | 한계 |
|---|---|---|---|
| 정상 검토 | `monthly-collaboration` | 분석안→검토→승인 대기, 승인 전 linkage 없음 | fake 응답은 내용 품질 증거가 아님 |
| 근거 보완 | `monthly-evidence-loop` | 검토자의 원천 요청→조회 결과→두 번째 계획→재검토, 재시작 후 메시지 중복 없음 | 명시적 원천 확인 요청을 사용한 절차 시연 |
| 사람 확인 | fake 서버 `LLM_MAX_CALLS=2`에서 `monthly-evidence-loop` | 검토/조회 후 호출 한도, `needs_human`, plan null, 담당자 승인 대기 | 실제 정책 부재나 고립 여부의 실증이 아닌 상한 시연 |

두 번째와 세 번째는 오류·보완 경로를 보여주는 절차 사례다. 잠금 평가의 실제 모델 결과에서 정상/수정/보류 사례를 선정하고 선정 이유를 남기는 작업은 live·사람 평가 후 수행한다. 현재 절차 시연을 유리한 성능 사례로 대체 인용하지 않는다. `monthly-resource-research`에서는 별도로 후보/검증 자원의 구분을 확인한다.

안전한 공개 시연 서버 설정:

```sh
DATA_MODE=sample LLM_MODE=fake OPENAI_API_KEY='' GOV24_SERVICE_KEY='' \
PERSON_MCP_MODE=stub RESOURCE_CATALOG=fixture LLM_MAX_CALLS=6 make dev
```

사람 확인 시연만 `LLM_MAX_CALLS=2`로 바꿔 새 실행을 만든다. 기존 실행의 호출·예약 비용 기록은 지우지 않는다. 각 시연 뒤 관찰 화면의 run ID와 trace, 승인 snapshot을 기록한다. 공개 캡처는 sample/fake만 사용한다.

## 예상 질문과 답변 초안

- **왜 개인을 찾지 않는가?** 제공 집계로 개인의 고립을 확정할 수 없다. 이번 범위는 지역 집단 검토 지원이며 개인 판정 확장은 후순위다.
- **왜 여러 에이전트인가?** 근거 요청·반론·수정 역할을 분리해 검토할 수 있다. 이 분리가 단일 에이전트보다 나은지는 잠금 비교와 사람 평정으로 확인해야 한다.
- **실시간인가?** 화면은 실행·승인·조회 결과에 반응한다. 지역 원천은 고정 기간 집계/주간 관측이며 실시간 센서 데이터가 아니다. 정책 API도 조회 시점·캐시 시점을 구분한다.
- **자원이 없으면?** 후보 조사를 수행하거나 사람 확인으로 남긴다. 미확인 자격·정원을 확정하지 않는다.
- **효과와 비용은?** fake 비용 0을 운영 비용으로 쓰지 않는다. 실제 실행의 토큰·예약·추정 비용·실패를 보존하고 독립 평정 전에는 개선 수치를 주장하지 않는다.

## 재현 패키지 경계

[제출 재현 절차](release.md)의 Git archive는 지정 커밋의 추적 파일만 담는다. 공개 후보에는 코드·합성 입력·테스트·공개 보고서·문서가 들어간다. `.env`, 실제 데이터, runtime DB, local 결과, 사용자 메모와 로컬 계획은 포함하지 않는다.

대회 전용 원본 묶음은 별도다. 무료·공개 여부와 원본 제출 권한을 자료별로 확인한 후 팀 담당자가 구성해야 한다. 권한 미확인 원본을 공개 Git 패키지에 넣지 않으며, 공개 코드 ZIP이 원본 제출 의무를 충족한다고 주장하지 않는다. manifest에는 커밋과 각 파일의 SHA-256을 기록하고 ZIP 내용과 대조한다.

다음 확인은 팀 담당자가 해야 한다: 최신 공식 양식/마감, 자료별 원본 제출 허용 여부, 독립 검토자 섭외·평정, 실제 모델 비교의 예산. 개발 검증 결과와 이 외부 확인의 상태를 함께 보고해야 한다.
