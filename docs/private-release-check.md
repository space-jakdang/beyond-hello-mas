# 비공개 지역 입력의 오프라인 인수 검사

선행 코드: `scripts.runtime_package`. 실제 입력을 저장소에 추가하지 않고 준비한 패키지 경로를 전달합니다. v1 계약은 보존하며 v2는 원래 2026-10-25 전달 폴더도 받아 원천 일치를 확인합니다.

```sh
uv run python -m scripts.check_regional_release /private/releases/input-v1
uv run python -m scripts.check_regional_release /private/releases/input-v2 \
  --source-delivery /private/input/에이전트용_20261025
```

두 버전 모두 별도 임시 실행 저장소와 외부 키 없는 fake 모델을 사용합니다. v1은 전체 경계 연결, 대표 지역 업무, 저장된 제안, 미래 합성 입력 격리와 패키지 불변을 확인합니다. v2는 전달본의 원천 해시와 `priority_1215.csv`를 고정 주 `2025-12-15`의 원천 단계명·카드 경보·최종 단계·순위에 대조합니다. 이어 514개 칸의 평가 상태 분모와 528개 카드 행·47개 경계를 확인하고, 양 지역의 남녀 업무가 담당자 검토 대기에 도달하는지, PDF/Word 보고서가 원천 연령과 고정 주를 보존하는지 확인합니다. 보류·근거 부족 셀은 최종 판정으로 승격하지 않습니다. 어떤 정책도 승인하거나 배분하지 않으며 v2는 미래 모델을 실행하지 않습니다. 임시 실행 저장소는 종료 시 삭제됩니다.

출력은 버전·기간·지역/성별/연령별 상태·집계 건수만 포함하며 원천 행·해시·경로·정책 본문·키·실행 DB를 내보내지 않습니다. 입력 패키지와 대조 대상 원천 파일은 수정하지 않습니다. v2에서 `permission_status=pending`이어도 이 로컬 검사만 실행할 수 있으며 그 결과는 반입 권한이나 서버 준비를 의미하지 않습니다. 실제 LLM/API 연동·정책 품질·운영 재시작·호스트 설정·모바일 UI는 확인하지 않습니다. fixture와 실제 운영 자료는 근거 수준을 구분해 기록합니다.

## 통합 이후의 별도 운영 관문

현재 진행 중인 UX와 방법론 변경을 통합한 코드 버전에서 다음을 추가 검증해야 합니다.

1. 실제 동네 이름·경계·집단 전체 선택과 결측 표시, 지도 선택→업무 요청의 동일 지역/기간 전달.
2. 실제 API로 지역 분석·통계 재검토·조건부 후보·정책 대안 3개·보고서 출처 확인. 생성 개수와 정책 품질은 별도로 기록.
3. 인증된 서버에서 브라우저 직접 링크/재접속·PDF/Word 다운로드·비인증 접근 차단 확인.
4. 서비스 프로세스 종료/기동 후 이전 실행과 승인 대기 조회, 실행 중 장애와 재시도에 따른 호출/비용 확인.
5. 관측·미래 합성·독립 평가의 출처/분모/미평가 표시 확인.

운영 결과에는 코드 SHA, 입력 manifest 해시, 검사 시각, 성공/실패/미실행, 모델·API 호출 기록을 남깁니다. 접근 가능한 호스팅과 통합 코드가 없으면 이 관문은 대기 상태입니다. 로컬 오프라인 통과를 운영 전체 성공으로 대신하지 않습니다.
