# 미래 시나리오 자동 분석

`POST /future/batches`에 `request_id`(UUID)와 `sgg`(강남구 `11230`, 춘천시 `32010`)를 보내면 다음 3개월의 합성 시나리오와 분석 업무를 함께 저장한다. `GET /future/batches/{id}`로 기간별 상태를 확인한다. 같은 요청 ID로 다시 보내도 새 업무를 만들지 않는다. 기존 GraphService가 기간 순서대로 실행하며 재시작 후 대기 업무를 복구한다. 한 로컬 서버 프로세스에서 사용하는 시연용 단발 큐다. 매달 실시간에 실행하는 운영 cron은 아니다.

시연 범위는 지역 전체 동의 청년·남성 요청 집단이다. 원천 자료의 실제 연령·성별 범위가 그 집단과 일치한다는 뜻은 아니다. 월별 기준자료는 최신 관측 월, 기간 집계는 원래 집계값을 이용한다. 고정 seed로 지수에 ±0.06 균등 변형과 가정된 주간 신호 2개를 추가한다. 원천 파일은 수정하지 않으며 생성 버전·seed·기준 입력 해시·변형 입력·가정·기간은 현재 모드의 runtime SQLite에 보관한다. AI는 이 별도 합성 입력을 분석한다. 생성기는 통계적 예측 모델이 아니며 미래 정확도를 입증하지 않는다.

합성 기간 분석도 기존 Supervisor → 지역 분석 → 통계 검토 → 자원 매칭 → 공무원 검토 경로와 비용 장부를 사용한다. 자원 기준일은 생성일이며 현재 정책을 미래 가정에 대입한다. 미래 모집·잔여 정원·예산·실제 배정을 확인한 결과가 아니다. 자동 실행은 제안 작성에서 멈추고 담당자 승인을 대신하지 않는다.

합성 미래 입력만 별도의 `FutureSegment` 월 계약을 사용한다. 기존 관측 데이터의 2025년 7~12월 검증은 유지한다. 일반 지역 업무에 미래 월을 넣는 것은 계속 거부한다. 합성 분석의 단계·추이·출처에는 명시적인 합성 플래그가 붙는다.

평가용 데이터 구성 및 일반화 검증은 [합성 데이터 문서](synthetic-datasets.md)를 따른다. 이 시연의 완료율을 실제 예측 정확도나 자원 적합성 점수로 사용하지 않는다.

두 가상 주간 신호는 시간순의 연속된 두 기간을 뜻하며 특정 카드 원천을 측정한 값이 아니다. 기준 자료에 한 동의 우선 청년 지수가 여러 개면 임의로 섞지 않고 입력을 거부한다. 기준 자료의 기간 집계 여부는 `baseline_period_aggregate`로 별도 보존하며 합성 행의 `source_file`에는 `synthetic:` 접두사를 붙인다. 실패한 기간은 재조회·재시작으로 자동 재시도하지 않는다.

지역 전체 동을 검토할 때 모델 입력의 출처 목록을 중복 제거하고 이미 facts에 전달한 연령·기간·플래그의 반복을 줄인다. 원본 통계 도구 결과와 모든 동의 근거 ID·값·상태는 저장하며 모델 입력 상한과 누적 비용 제한은 그대로 적용한다.
