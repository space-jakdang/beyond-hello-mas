# 지역 업무와 잠정 방법론

아래 regional-workflow-1 및 seohee-region-2 설명은 v3 입력과 기존 실행에 적용한다. 2026-10-25 지역 입력 계약은 문서 하단의 regional-workflow-2 절을 적용한다. 두 버전 모두 집단 조사용 개발 방법이며 개인 진단이 아니다. 과거 실행 스냅샷은 보존한다.

## 업무 계약

Supervisor → 지역 분석가 → 통계 분석가 → 자원 매칭 → Supervisor 제안 → 공무원 검토.

단계 수치와 통계 계산은 결정적 도구가 수행한다. 에이전트는 근거 확인·추가 분석 선택·해석·후속 행동을 담당한다. 모델이 숫자를 임의 수정하거나 미확인 자격을 승인할 수 없다. 기존 run/checkpoint/trace/승인 계약을 재사용한다.

새 흐름은 명시적 `workflow_version=regional-workflow-1`로 실행한다. 기존 시나리오와 평가를 보존한다. 모든 역할은 기존 실행별 호출 및 누적 비용 한도를 공유한다. 부족하면 미완료/보류를 반환하고 예산을 자동 증액하지 않는다.

## 잠정 지역 등급

원천별 기존 산식 `seohee-region-2`를 재사용한다. 계산된 등급의 개발용 해석은 1 일반 관찰, 2 변화 확인, 3 추가 조사, 4 우선 검토, 5 집중 검토다. 이는 조사 우선순위이며 지역 간 공통 절대 위험 척도가 아니다. 결측은 1이 아니라 null이다. 기존 청년 경계·원천 제공 단계는 새 실행에도 추적한다. 새 업무의 주간 카드 신호는 별도의 근거이며 지역 단계에 자동 가산하지 않는다. 기존 group_analysis의 주간 신호 가산/우선집단 처리와 구분하여 새 업무는 region_stage의 기본 단계를 사용한다.

자료 없는 월을 생성하지 않는다. 비교는 같은 지역·성·연령·지수·단위·기간에 한정한다. 기술통계와 민감도는 실제 위험 정확도가 아니다. 표본설계 없는 집계에 신뢰구간을 만들어 붙이지 않는다.

## 잠정 욕구 대응

개발 가정 `regional-needs-1`: 관측된 S1/v3와 활동·관계 신호는 relationship 조사 후보, 명시적 economic/housing/employment/health/emotional 구성요인은 같은 이름의 욕구 조사 후보로 연결한다. 구성요인은 유한한 수치가 양수인 경우만 사용한다. 원인·개인 욕구의 확정이 아니라 담당자 검토 가설이다. 해당 요인이 없으면 등급만으로 욕구를 만들지 않고 근거 부족으로 보류한다. 팀 검토 전에는 이 가정을 화면과 결과에 잠정으로 표시한다.

자원은 관할·원천 연령 범위·기준시점·유효기간·자격·단계 필터를 통과해야 한다. 원천 연령 범위가 불명확하면 보류한다. 추천은 최대 3건, shortfall은 3개 추천 슬롯의 부족이며 인원수/예산 부족이 아니다. 전체 집단이 자격을 충족한다는 뜻이 아니며 실제 서비스 제공 전 확인이 필요하다. 정책 API에서 찾은 항목은 별도 조사 후보다.

## 교환 산출물

모든 산출물은 run_id, 지역/집단, 관측기간, 원천, input_hash, methodology_version, 기준시점, evidence_id를 가진다. 지역 분석은 단계·요인·결측, 통계는 개수/분모·분포·비교범위·추가조회/보류, 매칭은 욕구 근거·추천/제외/부족, 제안은 위 산출물의 스냅샷을 묶는다. 승인 뒤 변경하면 새 실행·승인이 필요하다.

보완 요청은 사유와 원래 snapshot을 보존한 새 실행으로 연결한다. 재실행 전 원래 제안은 반려 처리하고 그 실행을 자동 승인하지 않는다. 복구 시 중복 자식 실행을 만들지 않는다. 승인은 로컬 검토 이력이며 외부 집행 완료가 아니다.

## 평가 계약

새 보고서 버전으로 기존 C5 비교를 보존한다. 개발 전에 고정하는 기본값:

- 등급: 같은 원천 척도의 기준 사례 일치율/MAE/혼동행렬, 보류 포함 전체 사례 분모. 과거 고정 계약의 참조4~5 누락은 제공 등급 보존 검사이며, 신규 공통 우선 검토 기준은 미확정이다.
- 자원: top-3 필수조건 위반 0, 관측 요인 근거 없는 추천 0. 적합성은 독립 평정이 없으면 null.
- 합성 데이터: seed 고정, 지역/기간/원천 가족별 분리, 결측·경계·자원 없음·유효기간·지원불가를 포함. LLM이 제안한 사례도 스키마/제약 검증 후 별도 라벨로 저장. 모델은 평가 라벨을 보지 않는다.
- 일반화: 미사용 실제 지역이 없으면 실제 외부 성능 null. 합성 제3지역은 프로토콜 견고성 시험이다. 동일 원천의 변형을 외부 검증으로 세지 않는다.
- A 결정적 도구, B 동일 도구 단일 에이전트, C 역할 분담을 같은 자료/스냅샷/호출·비용 한도로 비교. 계산 등급의 차이보다 근거 검토와 제안 성공을 측정한다. 성공은 필수조건 위반 없는 검토 가능한 제안 또는 참조상 적절한 보류다.
- 채택 기준 초안: 중대 오류 0, C 성공률이 B보다 최소 5%p 개선, 사전 고정된 예산 준수. 독립 평가가 없으면 채택 판단은 not_evaluated. 실패/timeout도 분모에 남긴다.

실제 효과·독립 라벨·기관 가용정원은 생성 데이터로 대체할 수 없다. [합성 데이터 원칙](synthetic-datasets.md)에 생성·사용·제한을 기록한다.

## 개발 계약 보충

- 버전 묶음: workflow-1은 seohee-region-2 기본 산식과 regional-needs-1을 고정 참조한다. 하나가 바뀌면 새 workflow 버전을 발급한다. data_mode/llm_mode/tool_version/model_version/prompt hash는 실행 기록과 산출물에서 추적하며 seed는 결정적 생성 데이터에만 적용한다.
- 욕구의 예외를 명시한다: 값이 존재하는 S1/v3 관측은 relationship **조사 가설**로 연결한다. 추가 허용 신호는 구성요인의 activity_deficit/relationship 양수다. 주간 카드 T1b/R1(직전 8주 중앙값 대비 변화)은 통계 참고만 하며 욕구나 등급에 가산하지 않는다.
- 중대 오류: 관측 밖 ID/허위 근거 추천, 필수 자격·관할·연령·유효기간 위반, 결측을 낮은 등급으로 대체, 승인 우회/과거 스냅샷 변조. 필터 위반 0은 안전 계약 지표이고 추천 품질 지표가 아니다. 기준시점에 자원 자료가 없으면 추천 0과 부족 사유를 기록한다.
- MAE와 혼동행렬은 동일 방법론·모집단 내에서만 계산한다. 과거 고정 계약의 “참조4~5 누락”은 제공 단계 보존 검사로만 읽는다. 신규 실행의 공통 우선 지표는 미평가이며 서로 다른 원천을 합치지 않는다. null 예측은 일치율 실패/누락에 포함하며 MAE는 판정 가능 쌍의 분모를 별도 표시한다.
- 제안 성공률 분모는 실패·보류를 포함한 전체 시도다. 제안 성공과 적절한 보류를 별도 집계한다. 독립 평정 없는 성공률/적합성/채택 종합은 null/not_evaluated다. 최소 24개 독립 사례, 가족(family_id) 단위로 묶은 짝지은 bootstrap 95% 구간의 C−B 하한>0 및 평균 차≥5%p, 중대 오류0을 개발용 채택 기준으로 둔다. 이 표본만으로 현장 효과를 주장하지 않는다.
- 합성 미지원 지역은 입력 거절 또는 지원불가 보류, 참조 정답이 없는 실제 전이는 null이면 계약 통과다. shortfall은 빈 슬롯수의 산술 일치만 검사하고 성능 가산점으로 쓰지 않는다.
- 기본 모델 호출 상한은 기존 설정의 실행당 4회다. 사용자가 설정한 값이 있으면 해당 값과 전체 흐름의 명시 한도 중 작은 값을 사용한다. 비용은 기존 누적 USD 장부 및 선택적 실행당 USD 상한을 사용한다. 평가가 한도를 초과하면 유료 호출을 시작하지 않는다.
- 보완 요청 멱등성은 parent_run_id를 키로 하여 부모당 보완 자식 하나를 연결한다. 기존 자식이 있으면 동일 요청은 반환하고 다른 요청은 충돌 처리한다. 자식에서 다시 보완 가능하나 서버 측 전체 보완 깊이 상한을 적용한다.
- 평가 입력과 정답 파일을 분리한다. 모델 호출에는 입력만 전달하고 생성/라벨 프롬프트·대화·캐시는 평가 호출에서 공유하지 않는다. 수정된 프롬프트/라벨은 hash와 새 평가 버전에 기록한다.

| 실행/검토 상태 | UI 표현 | 평가 처리 |
|---|---|---|
| not_started / running | 미실행 / 실행 중 | 완료 전 미측정 |
| completed / awaiting_approval | 완료 / 검토 대기 | 내용 평정과 별도 |
| needs_human / budget | 보류·사유 | 전체 분모 포함 |
| failed | 실패·오류 유형 | 실패 포함 |
| rejected / revision_requested | 반려 / 보완 요청 | 승인·도입 성공으로 세지 않음 |
| not_evaluated / null | 미평가 / 자료 없음 | 하위 종합도 미평가 |

## 통계 도구

`backend.tools.regional_statistics.run_tool`은 summary/trend/source_check/sensitivity/policy_insights와 지역 문맥 도구 regional_profile/regional_comparison을 받는다. 통계 검토에서 지역 도구는 미리 첨부한 regional_context가 있을 때만 선택할 수 있다. [지역 정보 계약](regional-context.md)을 참고한다. summary는 선택 관할 내 같은 지수·집단·원천기간·연령 범위의 동 분포다. trend는 개별 동의 실제 관측 월만 사용하며 월이 끊기거나 연령 범위가 달라지면 변화량은 null이다. sensitivity는 S1/v3 기본 지수 ±0.01의 단계 변화이며 주간 신호 가산이나 통계적 신뢰구간을 뜻하지 않는다. 비청년 지수는 민감도 미측정이다.

## 담당자 보완 요청

지역 업무의 승인 대기 제안에서 사유를 입력해 보완을 요청하면, 기존 제안을 반려하고 원래 업무 범위와 보완 사유를 가진 새 실행을 등록합니다. 새 실행은 분석부터 다시 수행하며 별도 승인이 필요합니다. 기존 스냅샷·담당자·사유·부모/자식 실행 연결을 보존합니다. 같은 스냅샷·담당자·사유의 재전송은 같은 자식 실행을 반환하고, 다른 요청이나 이미 결정된 제안은 충돌로 처리합니다. 보완은 최초 실행 이후 두 번까지 허용합니다.

`POST /runs/{run_id}/revision`은 `snapshot_version`, `operator`, `reason`을 받습니다. 원자료가 바뀌면 새 실행의 입력 해시도 바뀔 수 있습니다. 보완 요청 자체는 이전 단계 계산이나 외부 전달을 수정하지 않습니다. 승인과 반려는 로컬 기록이며 실제 기관 도입을 의미하지 않습니다.


분석·통계 역할에는 같은 잠정 방법론 버전, 1~5등급 의미, 요청 집단 정의, 실제 원자료 연령/성별 범위, 기간 집계 여부를 함께 전달한다. 기간 집계의 기준 월은 월별 실측을 주장하지 않는다. 이미 명시된 범위 차이는 한계로 설명하되 결측·불명확한 출처·과장된 사용은 계속 보류하거나 보완한다. 통계 역할의 검토 완료는 제한된 지역 우선순위 해석을 뜻하며 정책 자격이나 현장 타당성 승인이 아니다. 정책 원문 확인은 후속 조사 역할의 책임이다.

## 정책 매칭용 통계

통계 도구는 동일 지역·성별·연령·지수·원자료 기간·연령 범위 내에서 단계 분포, 결측, 필요 가설/미확정, 등급 중간순위를 계산한다. 공통 우선 기준이 없어 4~5 비율은 미평가(null)로 둔다. 비교 가능한 관측이 3개 미만이면 상대 위치는 미산출이다. 분모는 선택한 동·집단이며 주민 수나 유병률이 아니다. ±0.01 지수 변형의 기본 단계 민감도는 보정된 불확실성이 아니다.

측정된 필요 요인과 잠정 규칙을 구분한다. 지수만 있으면 관계 지원 가설로 제한하며 경제·주거 원인을 추정하지 않는다. 인구 분모와 서비스 이용·수용량은 추가 확인 자료로 남긴다. 통계 분석가는 이 요약으로 추이·출처·민감도 조회와 보류·재검토를 판단한다. 자원 매칭은 필요 가설과 등록 조건의 결정적 필터·순위 도구다. 지역 상대 위치나 분석가 우선 확인 순서를 자원 선택의 인과 근거로 설명하지 않는다.

업무 화면의 ‘통계 근거’에서 집단 요약과 선택한 동의 해석을 볼 수 있다. 전체 계산은 실행 스냅샷과 추천 결정 근거에 보존하고, 모델 입력에는 중복된 개별 프로필을 제거한 요약을 사용한다. 등급·필요 규칙은 개발 가정이며 실제 지원 효과는 별도 평가해야 한다.

## 전체 집단 업무
지역 업무의 성별·연령 전체 선택은 최대 8개 단일 집단 업무를 부모 실행으로 묶습니다. 최초 입력을 고정하며 같은 요청 키는 원천이 갱신되어도 기존 실행을 반환합니다. 기본 관측 없음·실행 실패·검토 대기를 구별하고 중단 후 이어가기는 아직 끝나지 않은 집단만 진행합니다. 취소는 진행 중인 호출을 강제 중단하지 않고 다음 집단부터 적용합니다. 부모별 비용은 LLM_RUN_BUDGET_USD가 설정되어 있으면 공유하며 전체 누적 비용 상한도 유지됩니다. 주간 관측 선택은 맥락으로 보존하고 기본 지수 등급을 변경하지 않습니다.

전체 업무는 단일 서버 프로세스에서 순차 실행합니다. 다중 worker 실행은 지원하지 않습니다. 호출 수 상한은 각 집단의 기존 LLM_MAX_CALLS(최대8집단), 비용 상한은 부모 공유 및 기존 전체 누적 상한입니다. 새로고침 후 동일 조건 요청은 브라우저 세션의 실행 의도를 재사용하며 새 실행 준비 버튼으로 명시적으로 새 업무를 만들 수 있습니다. 원천과 카탈로그는 최초 스냅샷을 사용하고 정부24 실시간 상세의 조회 시각은 별도로 보존합니다.

## 전체 범위와 새 정책 대안
성별·연령집단 전체 요청은 최대 8개 집단의 고정 입력 실행으로 확장합니다. 동별 원천·기간·등급을 보존하고 서로 다른 집단의 등급을 평균하지 않습니다. 통계는 같은 원천 범위의 다른 동 비교와 연속 관측의 변화 방향을 정책 검토에 전달하며 실제 수요 인원·인과 효과로 해석하지 않습니다. 기존 지원 후보와 별개로 동별 세 정책 대안을 작성하고, 근거 부족·모델 장애는 명시적 구상안으로 제공합니다. 동별 정책 대안 3개는 유지한다. 기존 전달 방식 개선과 현상 유지도 대안이며, 근거가 없으면 구상안으로 표시한다. 조사 요청 이유와 다음 확인 행동을 남긴다. 승인·기관 전달·자원 배정·정책 시행은 별개다. 감사 trace는 보존하고 실제 전후 값에 연결된 변경만 요약한다. Supervisor는 코드 기반 실행 조정자다.

### 원천별 지원 범위

로컬 전달 집계의 기준 상태는 `9e7d160`의 export 계약이다. 아래는 원천 구조이며 행 수나 성능 정답이 아니다. 새 입력에서는 source_period/source_bands/flags/hash를 다시 확인한다.

| 집단 (남·여 각각) | 원천 / 계산 가능한 기본 단계 | 관측·비교 범위 | 필요 연결 한계 |

## 원천별 욕구 근거 출력 v2

`regional-needs-2`는 원천 지수·관측 요인과 서비스 욕구를 구별한다. S1/v3의 유한한 관측은 단계1을 포함해 관계 지원 **조사 가설**만 만든다(`mapping_status=index_hypothesis`). 비청년 구조·가시성 지수, 임의의 양수 economic/housing/health 등의 필드명은 서비스 필요로 변환하지 않는다. 원천 요인의 유한한 값은 음수까지 `observed_factors`로 보존하고 정의·욕구 매핑이 확인되지 않았음을 표시한다. 청년 인구 수는 요인 대신 성별 공통 `population_context`로 분리하며 서비스 수요로 해석하지 않는다. 무효 요인은 별도 목록, 원래 입력은 결정 근거에 보존한다.

`unmapped_evidence`는 원천 요인 정의·욕구별 측정 자료와 현장 확인이 필요하다는 뜻이고, `insufficient_observation`은 지수 관측 보완이 먼저라는 뜻이다. 모든 프로필에 필요한 자료·다음 행동을 포함한다. 자원 후보를 만들지 못한 결과는 추천 성공으로 세지 않는다. 현재 전달본의 비청년 욕구 추가 매핑은 방법론 근거 미확보 상태이며 새 욕구를 생성하지 않는다. 원천 export의 구조·가시성·성별 공통 청년 인구 필드와 원본 해시 검증은 유지한다. 과거 regional-needs-1 결과를 덮어쓰지 않는다.

## 단계 척도와 우선 검토 상태

기본 계산은 유지한다. `base_stage`와 `stage_scale`은 원천별 기본 단계를 보존하고, S1/v3의 5개 지수 구간은 기본 [3,3,3,2,1]로 대응한다(도달 가능 단계1~3). 비청년 제공/구내 순위 단계는1~5다. 두 척도는 같은 절대 위험을 뜻하지 않는다. 공통1~5척도 및 집단별 우선 검토 기준은 미확정이므로 `priority_review`, 집단별 `priority_segments`/`priority_share`는 null, `priority_criterion_status=not_established`다. 청년 기본4~5 비율0을 낮은 우선순위의 근거로 제시하지 않는다.

지도는 `base_stage`와 선택한 주간 `exploratory_stage`를 구분한다. 탐색 표시의 기존 stage 계산과 남성20대 가산은 보존하되 시군구×성×카드연령 신호임을 설명하며 개인 위험이나 기본 지수로 합치지 않는다. 기본 관측을 지역 업무로 넘길 때 base_stage가 일치한다. 미래 합성 신호는 `scenario_stage`로 따로 남긴다.

`regional-candidates-2`는 자원의 개인 지원 단계/강도와 지역 조사 단계를 직접 대조해 자격을 확정하거나 제외하지 않는다. 등록 단계/강도는 원래 자원에 보존하고 `support_stage` 또는 `support_intensity=unknown`을 조건부 후보의 확인 과제로 남긴다. 개인 경로는 기존 단계/강도 필터를 유지한다. 별도 매칭 모델이 남아 있는 버전에서는 기존 통계 도구와 같은 열 이름+행 배열로 모델 문맥만 압축하고 전체 조건 기록은 유지한다. 과거 실행·승인 스냅샷은 재계산하지 않는다.

## 정보 추가와 최종 재검토 v2

새 관측의 `review_contract_version=statistics-review-2`는 충분한 summary만으로 검토를 마칠 수 있다. 이미 포함된 policy_insights 재조회는 거절하고 새 정보가 필요한 추이·출처·민감도를 조회한다. 미리 첨부한 regional_context가 있으면 지역 프로필·비교도 조회할 수 있다. 출처 확인 도구는 저장된 원천 범위를 확인하며 외부 출처의 독립 검증이 아니다.

최초 검토는 최대4판단·서로 다른 도구3회다. 보완은1회만 허용하고, 수정된 분석을 통계 모델에 실제로 다시 전달해 최종 검토1회를 수행한다. 최종 검토는 finish 또는 human만 가능하다. 추가 수정/조회·미해결 차단 근거·예산/시간/호출 한도 부족·모델 실패는 보류한다. ID 일치만으로 reviewed를 부여하지 않는다. `initial_plan`, `revised_plan`, `review_history`와 실제 호출 장부를 보존하며, `revision_check=final_statistics_review`는 최종 검토를 통과한 경우만 기록한다. 과거 버전 출력은 재계산하지 않고 버전 필드가 없는 복구 경로는 기존 규칙을 유지한다. 분석·통계·매칭의 같은 120초 경계를 확인하고 실행별 호출·비용 한도를 공유하며 자동 증액하지 않는다. 정책 후속의 개별 timeout까지 포함한 전체 업무의 120초 완료 보장은 아니다. 검토 단계 호출 감소와 전체 정책 작성 비용·추천 품질은 별도로 측정한다.

## 결정적 지역 매칭

새 관측은 `matching_mode=deterministic-regional-1`을 저장한다. 통계 검토 뒤 계산 도구가 조건부 후보를 그대로 반환하며 별도 선택·설명 모델 호출은0회다. `regional-candidates-3`의 순위는 욕구 가설 일치 수 내림차순 → 미확인 조건 수 오름차순 → 자원ID 오름차순이다. 마지막 기준은 재현 가능한 동률 해소이며 효과·자원 배분의 최적 순위가 아니다. 후보의 실제 검사와 `rank_factors`에서 설명을 작성하고 저장 근거·화면·평가에서 같은 순서를 보존한다. 분석가 priority_evidence_ids는 지역 검토 순서이며 이 자원 순위에 반영되지 않는다.

새 실행의 matching.model_calls=0과 실제 llm_calls 역할 장부를 대조한다. 실패·근거 부족·빈 후보는 보류이며 모델 성공으로 표시하지 않는다. 호출을 절약한 예산을 정책 작성에서 사용할 수 있으므로 전체 비용 감소나 추천 품질 개선은 별도 검증 대상이다. metadata에 matching_mode가 없는 과거 체크포인트는 기존 LLM 선택 경로를 유지하고 저장된 과거 모델 설명·승인·비용·순서는 변경하지 않는다.

### 정책 공백과 조사 사유 (`policy-gap-1`)

신규 업무의 `shortfall`/`recommendation_slot_shortfall`은 최대 3개 표시 슬롯 중 빈 수다. 후보 하나가 필요 가설을 모두 다루면 추가 검색을 요구하지 않는다. `policy_gap`은 관측 부족, 필요 미확정, 매칭 미완료, 미충족 필요 가설, 카탈로그 후보 없음, 자격 미확인, 후보 범위 충족을 구별한다. 자격 미확인에는 개인 조건 확인을 안내하며, 숫자를 채우기 위한 신규 정책 검색으로 대체하지 않는다. 미충족 가설은 기존 `research_gaps` 옵션, 명시 조사 요청은 `policy_research_requested=true`로 조사한다.

검색 실패·한도·범위 미완료와 범위 내 확인 후보 0건을 구별한다. 결과의 `search_scope`는 조사 범위이며 후보 개수는 지역별 개인 적합성 검증 수가 아니다. `field_gap_status=not_evaluated`, `absence_established=false`를 유지한다. 기존 `gap_count`는 조사 필요 행 수이며 `gap_count_definition`과 `research_request_count`로 뜻을 명시한다.

동별 운영 대안 3개는 계속 제공한다. 필요가 미확정이면 구상안과 확인 계획이며, 정확한 인용과 관측 연결만으로 현지 효과·실현 가능성이 확인되지는 않는다. `claim_limits`가 이를 구별한다. 후속 설계는 저장된 원문을 재사용하고 필요·요청이 없는 추가 사례 검색을 생략한다. 검색 캐시는 관할·검색어·대상·기준일을 구분한다. 버전 표시가 없는 과거 실행의 조사·출력 계약은 유지한다.

### 저장된 판단 보완 결과

지역 업무와 담당자 검토함의 같은 결과 컴포넌트는 최초 분석·보완 초안·최종 통계 재검토 기록을 연결한다. 저장된 요약이나 우선 확인 순서가 달라진 항목만 비교하며, 최종 재검토 미완료 초안은 현재 판단에 반영하지 않는다. 보완이 없거나 과거 실행에 전후 기록이 없으면 그 사실을 표시한다. 진행 기록과 감사 trace는 상세에서 계속 조회할 수 있다. 후보별 필요/자격/검색 상태와 다음 확인 행동은 실제 `policy_gap`을 사용하며 이해도 개선 수치를 뜻하지 않는다.


## 2026-10-25 지역 workflow 계약 2

regional-workflow-2는 입력 스키마 4와 판정 버전 seohee-region-20261025-1을 사용하는 새 지역 업무다. 위의 regional-workflow-1 동작과 seohee-region-2는 v3 및 이미 저장된 실행의 해석에 남긴다. regional-decision-2, regional-needs-2 등 기존 출력 하위 계약은 새 실행에서도 각각의 필드가 존재할 때만 사용하며, 기존 실행을 새 규칙으로 다시 읽거나 저장하지 않는다.

동 단계는 dong_stage_age.csv의 제공 결과를 보존한다. 강남은 20·30·40·50·60대와 70대 이상, 춘천은 제공된 20·30·40·50대와 60대 이상 원천 연령으로 분리한다. 자료가 묶은 연령은 source_bands에 원천 구간을 남기며, 서로 다른 원천 구간을 같은 표시 세대라는 이유로 합치지 않는다. 원천 단계 -1은 근거 부족, 0은 인구 기준 보류(강남 500명 미만, 춘천 300명 미만)로 유지한다. 춘천 30·40대의 근거 부족을 안정 단계로 해석하지 않는다. 서울 40대 이상에서 같은 성·연령대 서울 대비 1.5배 이상인 구조 위험은 제공된 약점 근거로 보존하며 개인 위험이나 별도 단계로 바꾸지 않는다.

주간 카드 입력은 V(활동)·N(생필품) 관측의 제공 경보 단계를 사용한다. 집단·연령·관측 주가 일치하는 두 경보 중 낮은 경보 단계를 결합하며, 선택 기준선은 직전 최대 8개 관측 주 중 최소 6주가 있을 때만 유효하다. 기준선 미산출, 명절 제외와 관측 누락은 정상 관측과 구별한다. 결합 경보가 강할 때만 유효 기본 단계를 최대 5까지 1단계 올리고, 약한 경보는 단계를 올리지 않는다. 인구 보류·근거 부족에는 단계를 만들지 않는다. 춘천 60대 이상 카드 결합은 제공된 교차표에 따라 원천 60대·70대 이상 경보 중 높은 값을 사용한다.

우선집단 신호는 단계 가산 없이 같은 최종 단계 안에서만 정렬에 사용한다. 전체 정렬은 최종 단계, 경보 강도, 우선집단, 약점 수, 인구 순이며 다섯 기준을 모두 내림차순으로 정렬한다. 완전 동률은 원천 입력 순서를 보존한다. 순위는 지원 배정·효과·개인 위험 순위를 뜻하지 않는다. 카드 CSV에 없는 원시 카드 값이나 기준선 수치는 복원·추정하지 않는다.

검증·운영에서 regional-workflow-2는 지역·성별·원천 연령·관측 주·입력 해시와 판정 버전을 한 실행에 고정한다. 지도, 지역 업무, 통계와 보고서는 같은 기본 단계·경보·최종 단계·상태를 사용한다. 공개 문서와 합성 테스트에서는 실제 개인별 레코드를 쓰지 않는다.
